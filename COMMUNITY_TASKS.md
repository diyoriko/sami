### P1: Аналитика — расширение метрик + формат DM

Порядок: сначала расширить дерево метрик, потом переформатировать DM.

**Шаг 1 — Расширить метрики (db + analytics):**
- [ ] Top-5 видео по completions за день
- [ ] Retention: сколько вчерашних активных вернулись сегодня

- [ ] Breakdown постов: видео vs текст (fallback) — масштаб проблемы с загрузкой
- [ ] Всего completions и активных пользователей за всё время (cumulative)

**Шаг 2 — Расширить данные для стратега:**
- [ ] **analytics-latest.json:** добавить новые метрики из шага 1
- [ ] **community-latest.json:** история постов за неделю с метриками (views, completions, forwards), активные пользователи

**Шаг 3 — Переформатировать DM админу:**
- [ ] Ежедневная аналитика: человечный формат вместо лога, с новыми метриками
- [ ] Недельный дашборд: читабельный формат с трендами
- [ ] Deploy notification: очеловечить, не показывать raw commit / Co-Authored-By

**Отдельно:**
- [ ] **Ликвидировать галлюцинации в ресерче:** стратег ссылается на несуществующие источники (Telemetr.io, Telegram Creator Hub). Либо дать веб-доступ, либо собирать дайджест конкурентов скриптом и класть в контекст

### P1: Стратег — память и feedback loop

- [ ] **Передавать последние 3-5 резюме прошлых отчётов** в промпт стратега (чтобы не начинал с нуля каждый день)
- [ ] **Трекер экспериментов:** JSON/SQLite — что предложил, что внедрено, результат. Стратег читает при генерации отчёта
- [ ] **Лог решений владельца:** стратег должен знать, что было отклонено/принято и почему (например: "UGC отложен до 50 подписчиков")

### P1: Стратег — веб-доступ и реальный ресерч

- [ ] Включить веб-поиск для стратега (STRATEGIST_ENABLE_WEB_SEARCH=1 или предварительный дайджест)
- [ ] Парсинг конкурентов: TGStat/Telemetr.io данные по fitness/wellness каналам РФ — автоматический сбор в файл контекста
- [ ] Бенчмарки: средние метрики для каналов 0-100, 100-1000, 1000+ подписчиков

### P1: Стратег — агентность (действия, а не только текст)

- [ ] COMMUNITY_PACKET v2: стратег формирует конкретные действия (создать опрос, текст welcome-сообщения, A/B варианты названий постов)
- [ ] Бот умеет выполнять действия из пакета: создать опрос в группе, изменить welcome-текст
- [ ] Feedback: бот отправляет стратегу результат выполненных действий (опрос создан, N голосов, результат)

### P1: Формат постов

- [ ] Теги каждый на отдельной строке, не через пробел
- [ ] Строка автора -> "Автор: YouTube" (ссылка внутри слова)

### P1: Наблюдаемость и алертинг

- [ ] **Алерт с первого фейла** — сейчас DM админу только после 3 подряд. Первый фейл постинга должен сразу уведомлять с причиной.
- [ ] **Structured logging** — заменить console.log с ad-hoc префиксами на структурированный логгер с correlation ID (один ID на весь путь: поиск → одобрение → скачивание → публикация).

### P1: Защита от внешних API

- [ ] **Timeout на YouTube API fetch** — сейчас без таймаута, запрос может висеть бесконечно и блокировать approval flow.
- [ ] **Circuit breaker** — после N фейлов YouTube API перестать долбить, использовать кэшированные видео, уведомить админа.
- [ ] **Rate limiting на callback-кнопки** — "Я сделал(а)" можно спамить, искусственно накручивая счётчик.

### P1: Целостность данных

- [ ] **Soft delete вместо DELETE** — добавить deleted_at во все таблицы. Сейчас UGC, баны, отклонения удаляются безвозвратно — нет аудита, нет паттернов спама.
- [ ] **Отдельный API-ключ для стратега** — /packet авторизуется тем же TELEGRAM_BOT_TOKEN. Утечка одного = контроль над всем. Добавить STRATEGIST_API_KEY.
- [ ] **Трекинг активности пользователей** — members таблица не хранит last_activity_at, completions_total, статус. Невозможно найти churned пользователей.
